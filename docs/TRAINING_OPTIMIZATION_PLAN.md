# 事前学習条件の最適化と実機精度改善計画

## 目的と制約

ODLを使わず32クラス分類を改善する。最良条件を実機へ書き込み、全32状態で32/32を目標にする。反復測定では98%以上（160判定なら157件以上）も確認する。達成を保証せず、未達時は混同クラスの追加データで反復する。Stamp側で特徴計算は行わない。

## 実行順序

1. 既に実行中の転送方式比較を完了する。FRAM音声キャッシュ版と従来版を同一モデル・ODLなし・32状態×5回で比較する。正式評価は従来転送方式に固定する。
2. 評価専用音声を全32状態×10フレーム＋全閉基準10フレームで2セッション確保する。セッション名に `holdout_eval` を付け、ファイル一覧・SHA256を固定する。収録順序を変える。学習セッションの自動列挙は禁止し、許可リストを使う。
3. 既存Stamp 13セッション＋新規3セッションを固定し、セッション単位の検証分割を作る。UNO Qは追加する条件だけで学習に含める。評価専用音声とその基準音を、学習・正規化統計・cross-baseline・早期終了に使わない。
4. 同一分割・同一seed 0/1/2で下表の条件を比較する。評価は実機相当int8前段・bf16ヘッドをPCで再現する。評価専用セットによる順位付けはモデル選択として扱い、最終的な未知データ精度とは区別する。
5. 最良条件のモデルを別名で保存し、学習条件・データ一覧・モデルSHA256・各クラスの正解率・混同行列を記録する。現行モデルを上書きせず保全する。
6. 最良候補を従来転送方式の実機サーベイへ書き込み、ODLなしで32状態×5回を実施する。別の32状態1巡も32/32を確認する。
7. 32/32に届かない場合、誤分類状態と取り違え先の両方を各20フレーム追加収録する。評価専用セットを学習へ流用しない。既存学習データを維持して再学習し、新しい実機サーベイで再評価する。95%以下なら継続、95%超でも98%以上と32/32を目標に改善する。
8. 改善が停滞した場合は同じ作業を漫然と繰り返さず、モデル劣化・ラベル・機構・時間帯・音響的な識別困難性を確認して報告する。

## 条件表

| 項目 | 比較条件 |
|---|---|
| 学習ハード | Stampのみ／Stamp＋UNO Q |
| 比例周波数シフト | ±0.5%／±1%／±2% |
| cross-baseline | 2本／4本 |
| 特徴ノイズ | なし／標準化空間で最大標準偏差0.05／0.15 |
| seed | 0、1、2 |

全組合せではなく、基準条件から一項目ずつ変える7条件×ハード2条件の14条件を一次比較する。特徴ノイズは波形への実環境雑音追加ではない。録音ノイズの効果を検証する場合は別実験として明記する。

## 判定と報告

セッション単位の32クラス精度、14クラス精度、平均・最低セッション精度、クラス別正解率、混同先を保存する。PC評価だけで改善確定とせず、新規実機測定で確認する。

評価音声確保、各条件完了、最良条件選定、実機評価、追加収録、再学習の各節目で進捗と結果を報告する。処理失敗時は後段へ進まず、原因を修正する。
